# Hangar

A self-hosted manager for your model-kit collection (gunpla, figures, LEGO, etc.).
Track each kit's grade, scale, limited edition, status, storage location, tags,
and photos — with EXIF metadata (device, exposure, GPS → address) shown on a
full-screen lightbox.

> **Disclaimer: this project is 100% a vibe-coding artifact.**
> It is currently an **MVP**: the UI satisfies the functional requirements and
> not much more. Expect rough edges, opinionated layouts, and minimal polish.
>
> **Contributor: TraeCode with Qwen3.8-Flash** — all code in this repository
> was generated by AI agents under human direction.

## Features

- **REST API + built-in web UI** in one small container (FastAPI + SQLite, no frontend framework)
- **First-run setup wizard**: set your login token, define hard enums (category / status)
  and soft enum suggestions (grade / limited / origin / storage / owner), optional
  Amap (Gaode) API key for reverse geocoding
- **Read-only browsing** without login; writes require the `X-API-Key` token
- **Photo upload** with per-record gallery, full-screen lightbox, and **EXIF display**
  (capture time, device, focal length / aperture / shutter / ISO)
- **GPS → address** via Amap reverse geocoding (WGS-84 → GCJ-02 conversion built in),
  with a persistent local cache so repeated lookups are cheap; falls back to raw
  coordinates when no API key is configured
- **Tags** (max 3 per record) with colored badges, exact-match filtering, and suggestions
- **Grade logos** for common gunpla grades (HG / RG / MG / MGEX / PG / ...)
- **Responsive**: desktop table view, mobile card view with touch gestures
- **Light / dark theme** following system preference

## Quick start (Docker)

```bash
git clone https://github.com/ffexis/hangar-project-release.git
cd hangar-project-release
cp .env.example .env   # optional; leave API_TOKEN empty to use the setup wizard
docker compose up -d --build
```

Open `http://<host>:8333/`. On first run you will be redirected to a **setup page**
where you choose the login token, enum values, and an optional Amap key.

> ⚠️ **This tool is designed for LAN / intranet deployment only. Do not expose it
> to the public internet.** The login token is stored in plaintext (by design, so
> you can recover it with `cat /data/token.txt` inside the container if forgotten),
> GET endpoints are open without authentication, and there is no HTTPS / rate
> limiting / multi-user support.

If `API_TOKEN` is set in `.env`, the setup wizard is skipped and the instance is
bootstrapped with built-in default enums (legacy behavior).

## Configuration

| Env var      | Purpose                                                                 |
|--------------|-------------------------------------------------------------------------|
| `API_TOKEN`  | Optional. Pre-sets the login token and skips the setup wizard.          |
| `AMAP_KEY`   | Optional. Amap web-service key for GPS → address. Can also be set in setup. |
| `DATA_FILE`  | SQLite path (default `/data/models.db`, on the named volume).           |
| `PHOTOS_DIR` | Photo storage path (default `/app/photos`). Mount a volume here.        |

Data lives in two places: the `ledger_data` volume (SQLite: records, settings,
geo cache) and the photos directory (image files). Back both up.

## API overview

All endpoints under `/api/v1`. Reads are public; writes need `X-API-Key: <token>`.

```
GET    /api/v1/status                        # { initialized: bool }
POST   /api/v1/setup                         # first-run only
GET    /api/v1/models                        # list, supports ?status=&storage=&grade=&category=&owner=&tag=&q=&display=
GET    /api/v1/models/values                 # enum values & suggestions for filters/forms
POST   /api/v1/models                        # create (id auto-generated as M001…)
PATCH  /api/v1/models/{id}                   # partial update
DELETE /api/v1/models/{id}
POST   /api/v1/models/{id}/photos            # multipart upload (jpg/png/webp/gif, ≤20MB)
DELETE /api/v1/models/{id}/photos/{filename}
GET    /api/v1/models/{id}/photos/{filename}/meta  # EXIF + address (no auth)
```

## Development

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8333
```

Stack: Python 3.11+, FastAPI, Pillow (+piexif for tests), vanilla JS/CSS frontend.

## Known limitations

- Single-instance, single-token; no user accounts or roles
- No HTTPS, no CSRF protection (LAN assumption)
- Hard enums can only be defined at setup time; changing them later requires
  recreating the database
- The UI is functional, not beautiful. PRs welcome anyway.
